# code-spec 运行时可用性与回归收敛设计

## 1. 背景与目标

`code-spec` 已成为默认初始化协议，且面向用户的自然语言已迁移为中文。运行检查发现：新项目初始化后，默认 `openspec/business.md` 没有业务模块数据；依赖业务注册表的命令会将 Markdown 表头误当作模块记录，并以无关的 ID 格式错误失败。

本设计的目标是让空项目以明确、可操作的方式阻止业务流程，待用户填写真实业务模块后恢复正常运行；同时让测试和生成的 Skill 与新的中文 `code-spec` 基线一致。

## 2. 决策与边界

- 空项目不是可执行的业务工作区。用户必须先定义至少一个真实业务模块，才可运行依赖模块的 Change、状态、校验和上下文流程。
- 不注入 `MOD-001` 等虚假示例数据，避免示例被后续 Change 或 Requirement 错误引用为真实业务基线。
- 模块解析不依赖表头文本。中文、英文和自定义表头均可使用；模块数据仍必须满足 canonical `MOD-###` ID 和五列结构。
- 不恢复 `spec-driven` 或旧 Change 兼容，不改变 `MOD-###`、`CHG-YYYYMMDD-NNN`、JSON 字段、状态枚举或既有退出码语义。
- 本设计不改变版本检查产品逻辑；受限沙箱无法监听 `127.0.0.1` 的测试应在可监听的本机或 CI 复验。

## 3. 运行时设计

### 3.1 初始化

`init` 继续生成中文的空白 `openspec/business.md`。模板包含中文解释和一个不属于 Markdown 表格数据行的示例，提示作者填写实际业务模块。初始化本身、帮助、配置和 Schema 浏览不依赖业务注册表，因此保持可用。

### 3.2 业务注册表解析

`business-registry` 是解析业务表的唯一边界：

1. 忽略非表格行和 Markdown 分隔行。
2. 忽略任何表头行，不以标题语言或固定标题文本作为判定条件。
3. 仅将首列匹配 `MOD-###`、列数满足五列的行解析为模块。
4. 对格式像模块数据但违反模块约束的行保留严格诊断。
5. 没有有效模块时返回专用的“业务注册表为空”领域错误，而不是暴露表头的 ID 校验错误。

这使显示语言与数据协议解耦，同时仍保证业务数据的 canonical 结构严格有效。

### 3.3 CLI 错误契约

所有需要加载业务注册表的命令将专用空注册表错误映射为中文、可操作的人类提示，并以非零退出码结束。提示必须：

- 说明尚未定义任何业务模块；
- 指向 `openspec/business.md`；
- 给出可复制的 `MOD-001` 五列表格示例；
- 明确在完成建模前不会创建 Change 或修改索引、Spec、归档。

对于 `--json`，稳定字段、ID、状态值和退出码保持不变；可读的 `message`/`fix` 使用中文。其他解析失败（重复 ID、格式无效、不可读文件）继续保留各自的严格错误路径。

## 4. 测试与生成物

### 4.1 回归矩阵

新增或更新测试覆盖：

- 中文、英文和自定义表头下的有效模块解析；
- 仅有表头或完全空白时的专用空注册表错误；
- 初始化后的空项目执行 `status --all`、`validate --all` 非零退出且无副作用；
- 添加一个真实模块后，上述命令可正常执行；
- 所有中文人类输出与 `code-spec` 默认值；
- JSON 和其他稳定机器契约不变。

### 4.2 生成的 Skill

运行 `pnpm run generate:skills` 后产生的 13 个 `skills/**/SKILL.md` 是受管理生成物，必须与模板一同提交。保留 Skill 一致性测试，防止再次出现模板已中文化而提交产物仍为旧内容的漂移。

### 4.3 环境性测试

`test/core/version-check.test.ts` 需要监听回环地址。在当前沙箱中出现的 `EPERM listen 127.0.0.1` 归类为环境未验证，不应通过放宽超时、跳过产品逻辑或修改版本检查实现来掩盖。该文件在允许本地监听的 CI 或开发机单独运行并通过后，才可宣称完整测试通过。

## 5. 验收与验证顺序

验收条件：

1. 新初始化的空项目准确提示“先建立业务模块”，不再把表头报为非法 ID。
2. 填入真实模块后，`status --all` 和 `validate --all` 正常执行。
3. 类型检查、lint、构建和 Skill 一致性测试通过。
4. 除受限环境的版本检查监听问题外，全量测试通过；版本检查在可监听环境中单独通过。
5. 工作区没有未提交的受管理 Skill 漂移。

建议验证顺序：

```text
pnpm exec tsc --noEmit
pnpm run lint
pnpm run build
pnpm run generate:skills
pnpm vitest run <业务注册表与 CLI 回归测试>
pnpm test
git diff --check
```
